# 从问题选工具，从报告追到电路

以下流程提炼自《数字 IC 工作学习资料整理》，页码均为随附 PDF 的物理页。书中包含历史版本命令。生成命令前先读当前项目的 Make/Tcl、filelist、top、宏、库和许可证环境，按已安装版本帮助确定参数。将用户提供的日志、实际运行结果和建议执行的命令分开记录。

| 用户的问题 | 依据与操作 | 输出给工程师的证据 |
| --- | --- | --- |
| VCS 编译失败或时间不推进 | PDF 第 3–13 页。核对 filelist、源文件顺序、库、宏，再分别看编译与 simv 运行。时间停在同一时刻时，用调试运行检查反复执行的语句。 | 第一个错误、编译或运行阶段、具体文件/层次、最小复现输入 |
| 波形在哪一拍开始错误 | VCS 篇第 3–7 页、Verdi 篇第 190 页起。打开与本次编译相配的源代码和 FSDB，从输出的首个错误沿反查驱动和输入条件。缩小波形窗口后跟踪相关控制与数据。 | 同一时刻的预期值、采样值、驱动位置及其前一拍状态 |
| 静态检查告警能否关闭 | SpyGlass 篇第 143 页起。先还原工程输入和规则，再按报告位置追踪信号的声明、驱动、时钟或复位。 | 规则、层次、可触发条件，已有约束与待核对假设 |
| DC 综合得到意外结构 | DC 篇第 270 页起。先核对 RTL、顶层、库和约束；确认综合器能正确解析并链接层次，再解读面积或时序。 | 未解析引用、实际推断单元、发生变化的模块及比较条件 |
| PT 报告负 slack | PT/STA 篇第 351–356 页与《静态时序分析与逻辑设计》PDF 第 12 页。标明 max/min、起终点时钟、捕获边沿和分析角。setup 按要求时间减到达时间计算；hold 按到达时间减要求时间计算。 | 列出两者与 slack 的单位和符号，再解释是数据路径、时钟关系还是约束需要核对 |
| Formality 出现比较失败 | Formality 篇第 416–419 页。先对应 reference 和 implementation 的设计、库及黑盒边界，再从失败比较点回溯逻辑锥。 | 配对的两份设计、比较点、边界假设和首个可解释的逻辑差异 |

**VCS 入门练习**：若项目的 files.f 已包含 SV 设计与 tb_top，且现有环境支持这些选项，可用 `vcs -sverilog -f files.f -top tb_top -o simv` 展开编译，再用 `./simv -l run.log` 运行。它是从书中的两步流程推导出的命令骨架。UVM 工程从自己的构建入口取得库和 test 配置。若需 FSDB，在项目现有调试目标中确认 PLI 和 dump 范围。

**评审练习**：若现象是“仿真通过但芯片时序不满足”，先确认仿真中实际比较的事务，再选取 PT 中相应时钟域的一条路径。给出 launch/capture 边沿和 slack 计算。若现象是“coverage 已满但漏错”，按《UVM 实战》PDF 第 94–100 页沿 monitor → reference model → scoreboard 检查数据来源，做一次应触发差异的比较并核对输出。
