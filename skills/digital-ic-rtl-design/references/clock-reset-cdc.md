# 时钟、复位与跨域

## 时钟

优先使用 clock enable，不在普通 RTL 中用组合逻辑门控时钟。确需门控时使用技术库 ICG 和项目约束流程。生成时钟、分频时钟和 mux 时钟必须在 SDC/STA/CDC 中建模，不能只看 RTL 波形。

## 复位

记录每个域的复位源、极性、断言/释放方式和复位顺序。异步断言、同步释放是常见方案，但不是无条件模板；需考虑目标库、scan、低功耗和系统顺序。数据通路寄存器不一定都需 reset，但控制状态、valid 和影响外部可见行为的状态必须有确定的启动策略。

复位释放本身可能是 CDC/RDC 事件。各域分别同步释放；不要让同一异步 reset 的不同同步级直接参与跨域协议。检查短脉冲、局部复位、一个域先退出 reset、运行时 reset 和 reset 后首个 transaction。

## CDC 模式

| 场景 | 常见实现 | 必查风险 |
| --- | --- | --- |
| 单 bit 电平 | 目的域 2+ 级同步器 | 源信号稳定时间、MTBF、同步器属性 |
| 单 bit 脉冲 | toggle、stretch 或 handshake | 慢到快/快到慢丢脉冲、背靠背事件 |
| 多 bit 配置 | 稳定总线 + 同步 enable/handshake | 数据与控制相干性 |
| 连续多 bit 数据 | async FIFO | Gray 指针、full/empty、复位与约束 |
| 计数/状态 | Gray 编码或握手快照 | 位间偏斜、非法中间码 |

独立同步多 bit 总线通常会产生不相干采样。同步器解决亚稳传播概率，不自动解决事件丢失、数据一致性或协议活性。

## 证据

CDC/RDC 完成需要结构工具报告、约束审查和协议级仿真/形式证据。对 waiver 记录 crossing、结构、为何安全、假设如何被约束以及失效后果。

## 选择同步结构之前

记录源/目的时钟的频率范围、是否可停钟、最大事件速率、允许丢事件与否、最大 outstanding、数据保持窗口和复位顺序。单 bit 不等于一定适用两级同步：窄脉冲可能在慢域完全不可见，toggle 在两次观察之间翻转两次也会丢事件。

对每个方案写清代价：

- 电平同步：同步级前不能放未经评估的组合毛刺；首级输出只进入后续同步级，不参与普通控制逻辑。同步级数由 MTBF/库/频率/实现决定，不能承诺“两级必安全”。
- request/acknowledge：数据先稳定并保持至目标采样完成，ack 返回后才允许重用；定义并发重发、复位、停钟和 timeout 行为。
- 脉冲展宽：宽度和事件间隔必须覆盖最坏时钟关系；若系统不保证间隔，选择握手/计数/FIFO，而不是随意固定 N 拍。
- 多信号重汇合：两个独立同步的相关控制可能跨不同目的周期到达；检查 reconvergence，不能因每条路径都有同步器就关闭问题。

同步器属性、禁止重定时/复制、级间布局和约束要与实现工具配合。RTL 仿真一般不直接模拟模拟亚稳态；用相位/频比变化测试协议，用结构与实现证据评价亚稳传播风险。

## 运行中复位与恢复

复位断言可能异步改变组合控制；检查复位使两个原本同步信号变成不同步的 RDC。若允许一侧单独 reset，需要 epoch、重新握手或清队列协议；同步释放只解决该域的释放时序，不能自动恢复跨域事务一致性。

列出启动前提（例如 PLL lock、时钟可用、宏 ready），用明确同步后的条件进入服务。需要短脉冲捕获时，reset pulse width 不能靠 RTL 仿真波形推断物理实现保证。
