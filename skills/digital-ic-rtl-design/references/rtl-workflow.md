# 规格到 RTL 的门禁

## 1. 接口契约

在写 RTL 前补齐一张契约表：信号、方向、宽度/符号、时钟域、采样沿、复位值、有效条件、稳定性、允许组合路径。对 transaction 再定义接受条件、响应延迟、最大 outstanding、排序、背压和错误。

若规格只给了波形或例子，例子不是完整协议。提取不变量并标出未定义区间，例如：`valid && !ready` 时 payload 是否必须稳定；reset 期间输出是否有保证；请求被接受后能否取消。

## 2. 微架构检查点

- 状态：寄存器、队列、计数器、credit、tag、异常状态。
- 更新：每个状态量的唯一所有者、enable、优先级和 reset 值。
- 数据流：输入到输出的延迟、吞吐、旁路、stall 和 flush。
- 控制流：互斥/公平、资源冲突、锁死和饥饿。
- 边界：clock/reset domain、外部异步输入、宏/IP、DFT/低功耗控制。
- 不变量：占用范围、读写指针关系、响应不多于请求、接受的数据最终处理等。

优先选择能被简单断言和 scoreboard 观察的结构。性能优化必须指出代价：面积、关键路径、状态空间或验证复杂度。

## 3. 实现门禁

实现前：契约无关键歧义；参数边界已列出；CDC/RDC 方案已确定；异常与复位优先级已确定。

实现后：每个寄存器只在一个时序块驱动；组合块完整赋值；无隐式宽度陷阱；FSM 可恢复；握手在 stall 下稳定；复位释放安全；断言不观察错误采样区。

## 4. 完成定义

至少满足：语法/展开成功；目标 lint 无未解释的高严重度问题；关键 directed test 通过；新增行为有断言或 checker；参数边界被编译或仿真；所有 waiver 有原因、影响和责任人/后续动作。工具不可用时，把对应项写成“未验证”。
