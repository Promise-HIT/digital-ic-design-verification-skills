# SystemVerilog 语义与可综合性检查

在算术、参数化、综合/仿真不一致或未知值问题时读取。书籍用于解释机制；项目语言模式、库和实际工具决定支持范围。

## 从数学表达式到硬件

为每个高风险表达式记录：操作数位宽/符号 → 中间结果位宽 → 最终截断/舍入策略。不要认为赋给更宽变量就能挽救所有已经发生的中间溢出；表达式尺寸受上下文影响，应在运算前显式扩展并做极值测试。

- W 位无符号加法若需保留进位，可写 `{1'b0,a} + {1'b0,b}`，结果接 W+1 位；不能把这一形式直接用于有符号加法。
- 有符号扩展用符号位复制，算术操作数显式声明 `signed`。`$signed` 改变解释，不增加位宽。part-select/拼接的 signedness 需重新核对。
- `>>>` 是否符号填充取决于左操作数是否 signed；移位不会自动扩大左操作数。检查移位量 0、W-1、W、超范围及负数策略。
- 乘积、累加和定点计算分别定义全精度、guard bits、溢出、饱和/回绕、舍入/截断；不能以随机小数值测试替代极值。
- unsized literal、`integer/int`、混合 signed/unsigned 比较、条件运算符的两分支，是重点 lint 位置。转换前后至少测试 0、最大正数、最高位为 1 和 -1（若合法）。

## 参数与结构

使用 `localparam int AW = (DEPTH > 1) ? $clog2(DEPTH) : 1` 可避免深度 1 产生零位向量；占用计数位宽用能表示 DEPTH 的宽度，如 `$clog2(DEPTH+1)`。两者用途不同。

非 2 次幂指针必须显式在 DEPTH-1 回绕。`DEPTH=1` 的 RAM 读写冲突、空满和旁路需单独验证。generate 分支在每个合法配置实际展开；非法参数用工具支持的 elaboration 检查或仿真 `$fatal` 提前拒绝，不宣称仿真检查等于综合参数约束。

packed array 表达位向量/算术，unpacked array 表达元素集合；跨端口、struct、enum、package typedef 的形状和类型一致。package 先编译，include guard 不能解决 package 编译顺序。

## 调度与未知值

- `always_ff` 中寄存器使用 NBA；同一边沿所有 RHS 看的是更新前状态。检查多次赋值的优先级与跨块读写，不能依赖进程执行顺序。
- `always_comb` 给默认值再覆盖，但默认值不能掩盖未定义规格；避免读后写、过程自依赖和函数副作用造成敏感性问题。
- `unique/priority` 不替代 default，也不证明互斥；结合工具对不可能分支的优化理解。避免用综合 don't-care 将合法输入优化掉。
- 控制/valid/地址在有效窗口出现 X 应失败。TB 比较可用 `!==` 检测 X；协议只在有效时要求 payload 已知时，不应断言所有无效周期的数据均为已知。
- 2-state 仿真可能隐藏初始化/X 问题；`if` 的 X 乐观、算术的 X 悲观及 gate-level 行为分别分析。不得把“某工具看不到 X”作为 reset 证明。

## 存储器和实现目标

先确认 ASIC SRAM 宏或 FPGA RAM 的同步/异步读、读延迟、byte enable、read-during-write 模式。仿真数组不是已验证的宏替代品。大量复位存储单元可能阻止 RAM 推断，复位 valid/指针通常比复位整个 RAM 更合适，但须由规格允许。

将初始化、`initial`、内部三态、除法/取模、大桶形移位、动态循环与目标综合能力对应；“可综合”还需检查面积、时序和宏映射。不要把 FPGA 初始化策略无条件移植到 ASIC。
