# 数字 IC 开发闭环

用于新模块、跨模块功能或流程搭建。小改动只执行受影响环节，不强制产出全套文档。流程服务于规格、正确性和可复现证据。

## 任务起点

先判断任务属于：新 RTL、功能修改、验证环境、失败定位、综合/时序优化或阶段交付。明确 ASIC/FPGA、模块边界、已有 IP、目标工具/版本及可用运行环境。复用项目已有入口；缺少工具时仍完成可做的设计和静态检查，把缺口写清。

## 各阶段的输入、动作与退出条件

|阶段|核心输入|主要动作|退出条件/交付|
|---|---|---|---|
|需求与契约|功能说明、协议、系统约束|定义接受/完成、延迟/吞吐、顺序、复位/取消、异常和合法参数|关键行为可判定；影响正确性的歧义已澄清；其余假设显式记录|
|微架构|契约和性能目标|划分数据/控制路径、状态、缓存、资源冲突、时钟/复位域|状态更新有唯一所有者；容量/延迟可推导；关键不变量及验证方法明确|
|验证规划|需求与微架构风险|建立需求→激励→独立 checker→覆盖→证据；定义 reset/背压/边界矩阵|主路径和高风险失败有可观察判据；选择 procedural 或 UVM 有理由|
|最小实现|接口、状态更新表、存储语义|实现可运行主路径，随后补边界/恢复；遵守语言和项目风格|目标配置实际展开；无未解释 latch/多驱动/位宽问题|
|功能闭环|RTL、模型、testplan|定向测试锁定语义，再增加随机交互；新 checker 适度注错|数据和事务守恒成立；原 bug 重现转通过；结束无 outstanding|
|静态/实现闭环|时钟/复位/CDC 意图、SDC、库|按风险执行 lint、CDC/RDC、综合、属性证明/等价、STA|报告和约束一致；高严重度问题关闭或有明确依据的 waiver|
|物理实现交接/反馈|网表、SDC、宏/引脚/电源/DFT 意图|核对后端输入完整性；接收布局布线、寄生与时序/功耗反馈；必要时处理 ECO|交接条件明确；ECO 后按影响重做等价/功能/时序检查，不能沿用改动前结论|
|回归与交付|变更集、相关配置、检查结果|跑受影响回归，审查覆盖缺口和非目标配置影响|命令/版本/配置/seed/日志可复现；验证范围与未运行项清楚|

验证规划与微架构并行推进：若 checker 难以独立建立，回看契约或增加必要观察接口；不能等 RTL 全写完再决定“怎样算对”。

## 推荐迭代单位

以一个可检查的行为为单位：单事务正确 → 背靠背吞吐 → 背压/资源边界 → reset/flush/错误恢复 → 参数/多时钟组合。顺序按模块风险调整。每轮只改必要 RTL/TB，保留固定配置的快速 smoke，避免首轮就跑昂贵全量随机回归。

发现失败：固定输入和环境 → 找首个违反契约的时刻 → 分清 DUT/TB/约束/工具 → 最小反例 → 最小修复 → 原失败与邻近边界回归。约束收紧、checker 放宽或 seed 更换都不能替代修复证据。

## 按设计风险裁剪检查

- 纯组合算术：位宽/精度推导、极值、穷举小参数或独立数学模型；不必引入完整 UVM。
- 有状态单时钟模块：状态优先级、接受事件、reset、边界与 SVA/scoreboard；有时序目标时加入综合反馈。
- 多时钟/异步输入：先选择相干性和事件传递协议，再写 RTL；CDC/RDC 与物理约束不能由普通仿真替代。
- 协议/多 outstanding：把握手、身份、排序、超时、取消和资源释放作为一个整体；采用匹配规模的 agent/scoreboard。
- 性能优化：比较同一约束/库/模式下的面积、时序和吞吐，并验证新增流水延迟、sideband 和 flush 行为。

## 常见交付组织

沿用仓库目录。新工程无既定结构时，可按 `rtl/`、`tb/`、`constraints/`、`scripts/`、`reports/<run-id>/` 划分；小模块无需建空目录。一个入口应能选定 top、配置与测试，并保存结果。接口契约和关键假设放在评审可见的位置，详细工具日志留在运行目录。

仅需要阶段性前端交付时，不把“所有后端签核完成”设为阻断条件；明确交接清单和尚需的 CDC/STA/DFT/低功耗等证据。工具通过只能支持该工具、配置、模型和假设下的结论。
