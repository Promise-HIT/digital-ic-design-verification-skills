# 常用数字 IC 模块设计与验证路线

先选模块族，再读取相关语言/协议/跨域参考。下面给的是设计决策与判据，不是未经规格确认即可复制的通用 RTL。

## 模块选择表

|模块族|实现前必须确定|优先验证的边界|
|---|---|---|
|计数器/定时器/分频 enable|位宽、终值是否包含、饱和/回绕、load/clear/enable 优先级|0/1/最大值、终值同拍 load/clear、暂停恢复、非法参数|
|边沿/脉冲检测|信号所属时钟域、最小脉宽、事件间隔、是否允许丢事件|背靠背、持续高、复位释放、快慢时钟关系；异步事件先设计 CDC|
|FSM/控制器|输入采样、输出函数、状态保持、错误/取消优先级|非法状态、竞争条件、等待状态退出、超时与恢复|
|同步 FIFO|容量、RAM 读语义、满/空同时入出、旁路/寄存输出|深度 1/2/非 2 次幂、回绕、空满、数据守恒、reset/flush|
|异步 FIFO/握手桥|频率/停钟、事件速率、同步结构、共同/局部复位|相位/频比、满空跨域延迟、重汇合、一侧复位和恢复|
|仲裁器/调度器|优先级、接受/完成更新点、burst lock、公平前提|同拍请求、长期阻塞、轮转、取消、饥饿条件|
|ready/valid 缓冲/流水|允许组合路径、ready 反馈延迟、存储容量、flush|满速、单拍/长 stall、同时入出、payload/tag/error 同步|
|寄存器组/CSR|地址/对齐、byte enable、reset、权限、W1C/RC、硬件更新|读写冲突、部分写、读副作用、非法地址、软件/硬件同拍竞争|
|RAM/寄存器文件包装|端口数、读延迟、同地址读写模式、宏和初始化策略|同地址冲突、地址边界、byte mask、读 valid 对齐、宏模型一致性|
|固定点算术/MAC/舍入|signedness、全精度、中间位宽、缩放、溢出策略|最大正/负数、-1、0、进位、乘积极值、舍入临界、流水暂停|
|CRC/校验/编解码|多项式、位序、反射、初值、final XOR、有效尾字节|golden vector、单 bit、连续包、不同长度、seed reload|
|APB/AXI 等协议适配|匹配版协议、通道独立性、顺序/outstanding、错误响应|等待/背压、地址与数据到达顺序、响应阻塞、ID/长度/边界、reset|
|复位/时钟控制|目标库、同步释放、停钟、ICG/test-enable、域间顺序|启动、停钟恢复、短脉冲、模式切换、独立 reset；静态/实现证据|

协议名称不构成完整规格。实现 AXI/APB 时须获取匹配版本正式规范或已验证项目 VIP，不能只凭波形例子补全 burst、ID 或跨通道规则。

## 计数器与定时器

先手算事件到输出的拍数，例如从接受 `start` 到 `done` 是 N 还是 N+1 拍。定义 terminal compare 使用旧值还是 next 值，`done` 是单拍还是保持到 acknowledge。用一张状态优先级表处理 reset/clear/load/enable 同拍，避免分散 NBA 覆盖。

reference model 可用整数记录剩余事件次数，按真实 enable/接受事件推进；不复制 RTL 的截断计数表达式。定时器若依赖可停时钟，须说明计时暂停还是由独立时基继续。

## FIFO 与缓冲

先推导有效事件和容量，再选择指针/计数、RAM、旁路结构。`输入已接受 - 输出已接受 - 合法取消 = 当前存量` 是端到端判据；有顺序要求时进一步比较唯一序号及全部 sideband。实现与验证细节见 [protocol-boundaries.md](protocol-boundaries.md)。

skid buffer 不是简单打一拍 ready；反馈延迟内承诺接受的数据必须有位置保存。注册 data 时同步处理 valid/tag/error，flush 对所有字段具有一致语义。

## 仲裁与共享资源

把请求、授权、下游接受和事务完成分开。明确 winner 在阻塞期是否锁定，资源在何时释放，取消是否影响下一次优先级。以独立策略模型验证选择，以不变量检查 onehot0、无幽灵授权、无重复消费。

公平性检查必须写前提：持续请求、下游最终接受、有限 burst/lock 等。没有这些前提，有限等待上限不是可承诺性质。共享乘法器/存储端口/执行单元也按这一模型跟踪事务身份。

## CSR 与存储

CSR 将字段语义与总线时序分离建模。软件清除与硬件置位同拍时谁优先必须有规格依据；W1C 不能当普通 RW bit 做测试。byte enable、未实现位、只读位和返回错误均独立检查。需要 UVM RAL 时读取配套验证 skill 的寄存器参考。

RAM 模型必须匹配目标宏的读延迟和冲突语义。不要用 TB 里异步读数组掩盖实际 SRAM 的同步读行为；也不要为清空“无效数据”复位整个大 RAM 从而破坏推断。

## 算术与数据处理

从数学式写出每级范围和精度预算，再决定管线位置。reference model 使用足够精度的整数/数学实现，显式模拟硬件的舍入、饱和或回绕。验证既检查数值，也检查 latency、bubble、stall、flush 和 tag 对齐。

并行 CRC、编码和宽度变换同样需要字节/bit 顺序契约。不要将某本书的演示常量视为协议常量。

## 组合模块的验证最小集

每次只选择相关项：基本功能、所有合法边界、并发更新、backpressure、reset/flush、非法输入策略、参数组合、必要的静态/形式/实现检查。规模小的模块优先简单自检查 bench；系统级复用、复杂协议或多 agent 再引入 UVM。
